\secband{DESCRIPCIÓN GENERAL DEL PROYECTO}
El Proyecto Fin de Curso (PFC) consiste en elaborar de forma progresiva un documento de \textbf{Especificación de Requisitos de Software (ERS/SRS)} para un sistema \textbf{real}, siguiendo la estructura de IEEE/ISO/IEC 29148:2018. La Entrega 2 (1B) consolida la planificación y la elicitación de la 1A y construye la \textbf{especificación parcial}: requisitos formalizados, modelado UML inicial y priorización.

\begin{notabox}[title={Sistema objetivo (obligatorio)}]
\small Cada equipo selecciona un sistema de software \textbf{real} para una organización local (empresa, institución pública, emprendimiento, ONG, finca, cooperativa). \textbf{No se aceptan} sistemas ficticios ni genéricos sin cliente identificable. El sistema debe tener \textbf{al menos 3 tipos de usuarios} y \textbf{$\ge$15 requisitos funcionales} identificables.
\end{notabox}

\submark{Roles del equipo (deben evidenciarse)}

\secband{CONTENIDO ESPECÍFICO DE LA ENTREGA 2 (1B)}
\submark{3.1 Interfaces externas y \textit{mockups}}
Describir las interfaces de usuario (pantallas principales con \textit{mockups} de baja/alta fidelidad), de hardware y de software (integraciones, APIs, formatos de intercambio). Cada \textit{mockup} debe vincularse a los RF que soporta.

\submark{3.2 Requisitos funcionales — plantilla de 8 atributos}
Cada RF se documenta con: \textbf{(1)} identificador único, \textbf{(2)} nombre, \textbf{(3)} descripción, \textbf{(4)} actor/origen (evidencia), \textbf{(5)} entradas/salidas, \textbf{(6)} precondiciones/postcondiciones, \textbf{(7)} prioridad (MoSCoW), \textbf{(8)} criterio de verificación. Mínimo \textbf{15 RF}.

\submark{3.3 Requisitos no funcionales cuantificables (ISO/IEC 25010)}
Mínimo \textbf{6 NFR}, cada uno asociado a una característica de ISO/IEC 25010 y \textbf{cuantificado} con métrica y criterio de verificación. Términos vagos (``rápido'', ``seguro'', ``amigable'') sin cuantificar no se aceptan.

\submark{3.4 Modelado UML}
Diagrama de \textbf{casos de uso general} (todos los actores y el límite del sistema) + \textbf{$\ge$5 CU detallados textualmente} (flujo principal, alternativos, precondiciones/postcondiciones) y \textbf{diagrama de clases conceptual} ($\ge$8 clases con relaciones y multiplicidad). Todos los diagramas en herramienta CASE, en alta resolución.

\submark{3.5 Clasificación, priorización y trazabilidad (Apéndices C y D)}
Clasificar todos los requisitos (RF/NFR/restricción), priorizarlos con \textbf{MoSCoW} (justificando Must y Won't) y construir la \textbf{matriz de trazabilidad parcial} que enlace \textbf{evidencia de campo $\rightarrow$ requisito $\rightarrow$ caso de uso}.

El uso de la información es \textbf{exclusivamente académico}.
